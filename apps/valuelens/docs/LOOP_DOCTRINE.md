# ValueLens Loop Doctrine

## Prime belief

AI projects should not be funded because they sound clever. They should be funded because they can prove value, control risk, and survive post-launch audit.

## The loop

1. Input
   - AI idea
   - Business process
   - Codebase summary
   - Existing project plan

2. Value forecast
   - Estimate annual value
   - Estimate payback period
   - Record assumptions
   - Record confidence

3. Risk audit
   - Delivery risk
   - Data sensitivity
   - Compliance exposure
   - Human impact
   - Hallucination/customer harm risk

4. Build plan
   - Recommended first build
   - Human approval boundary
   - 30 / 60 / 90 day roadmap
   - Evidence gaps

5. Outcome ledger
   - Forecast value
   - Actual value
   - Forecast-vs-actual gap
   - Risk incidents
   - Adoption evidence

6. Correction loop
   - Classify the miss
   - Improve scoring rules
   - Promote, hold, or kill the project

## Product boundary

ValueLens can analyse a codebase, but it does not change production code. It creates a shadow audit and recommends safe next actions. Any high-risk automation defaults to human approval.

## Boardroom line

ValueLens helps organisations stop funding AI hype and start funding AI that pays back.
